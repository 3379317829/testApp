## 一、先把两份材料对齐

题目文件只说"交到 GitHub"，**提交说明**才是真正的交付标准，两条硬约束必须记住：

| 项 | 要求 |
|---|---|
| 提交物 | ① GitHub 仓库链接 ② **GitHub Pages 在线作品链接**（评委不下载、不安装，点开就能体验） |
| 仓库 | 必须 **Public**，含完整源码 + README，**≥3 次有实际意义的 Commit**（明说"不建议仅在结束前一次性上传"） |
| 技术形态 | Pages 只发静态前端 → **核心体验不得依赖未提供的服务器/后端** |
| 红线 | 严禁提交账号密码、API Key、Token 等敏感信息 |
| README | 产品名称、解决的问题、主要功能、运行/使用说明、自主设计的实用或创新内容 |

**结论：纯静态前端 + localStorage 持久化**，不走后端。这不是偷懒，是交付方式的硬要求。

## 三、考点分析：26 条材料里埋的坑（重点）

题目原文明确写了三句"送命题"：
- P031：*"材料中的时间、适用对象、参与条件、状态以及不同通知之间的关系，应由你根据题目内容自行判断。"*
- P032：*"题目没有提供的信息，请不要擅自编造。"*
- P033：*"对于存在缺失、不确定、更新或需要进一步判断的信息，应采用合理且对用户负责的方式进行呈现和处理。"*
- P027：*"如何兼顾开放参与、信息价值和平台使用秩序"* —— 这是产品思维的主考点。

据此逐条甄别出 **20 个坑**：

### A. 同一活动的多条通知（"关联"考点，最容易漏）
1. **01 ↔ 09 是同一活动的原通知与补充通知**：01 说"原计划 9 月 20 日起每周六 19:00 训练"，09 说"首次训练**改为 9 月 21 日 19:30**，地点改至**实验楼 A402**"。
   → 若把两条并列展示，用户会看到**已被推翻的旧时间**。必须合并，并显式标注"时间/地点已变更，以最新通知为准"。
2. **03 ↔ 20 是招募公告与补充说明**：03 招募开发/设计/材料成员（9/22 18:00 截止）；20 说"**开发方向名额已满**，现主要补充设计与材料成员"，且"已投递者无需重复提交"。
   → 合并后状态应为"开发已满，仅补设计与材料"。

### B. 状态不只是"开始/结束"（时间背景 = 9 月 19 日当天）
3. **10 前端开发经验交流会 9/19 15:00—16:30** → 考核进行中就是**正在进行**（不是"未开始"）。
4. **02 AI 应用入门公开课 9/19 19:00**、**18 网络安全小组首次交流 9/19 19:30** → **今天稍后开始**，应进"今日"视图并给"还有几小时"提示。
5. **04 数模分享会**：直播 9/18 19:30 **已结束**，但"活动方预计 **9 月 20 日上传回放**" → 状态是"已结束 · 回放待上线"，不是简单"已结束"。
6. **19 学生创新项目路演观摩**：原报名截止 9/18 22:00 **已过**，但"如现场仍有余位，可接受**候补入场**" → 不能粗暴标"已截止"，应标"报名已截止 · 可现场候补"。
7. **05 志愿服务**：活动 9/27，**报名 9/20 12:00 截止** → 未开始 + 报名窗口即将关闭（倒计时提醒的关键样本）。
8. **07 AI 创新应用挑战赛**：9/21 18:00 前"**校内意向登记**"，10/20 提交作品，且原文强调"**意向登记不等同于最终作品提交**" → 必须拆成**两个不同性质的截止时间**。
9. **14 Git 工作坊**：限 40 人，"**提交报名表不代表最终录取，以审核通知为准**" → 报名后状态是"**待审核**"，不是"已报名成功"。

### C. 字段缺失 / 不确定（不得编造，必须显式标注）
10. **12 全国高校计算机能力挑战赛**："具体**费用信息未提供**" → 显示"费用待公布"，不得写"免费"。
11. **16 校园摄影志愿者**：长期招募，"**报名截止时间未注明**" → 标"长期有效 · 截止时间未明确"。
12. **06 Web 开发学习小组**："**报名时间未注明，满员即止**" → 标"无名额/报名时间，满员即止"。
13. **22 羽毛球约球**："**场地待最终确认**"；**23 AI 工具搭子**："具体**地点未确定**"、时间只说"拟于 9 月 21 日晚" → 均属"待定"，不可补全成具体地点。
14. **25 数码新品体验交流**："活动时间、地点**未注明**"。

### D. 信息质量与平台秩序（产品思维主考点）
15. **24 学生发起｜"校园兼职福利分享"**：称"零门槛、日结"，要求**添加私人微信**获取详情，**未提供主办方、地点和完整内容** → 典型低可信/高风险信息，必须给**风险提示**，而不是平铺直叙展示。
16. **25 学生发起｜数码新品体验交流**：标题写"技术交流"，正文却是**商家优惠与购买链接** → **标题党/软广**，与校园活动关联弱，应标注"疑似推广"。
17. 学生自主发布共 4 条（22、23、24、25），**2 条有问题** → 这正是"开放发布 vs 信息价值 vs 使用秩序"的平衡题，产品必须给出机制（来源标签 + 可信度 + 风险提示），而不是一刀切删除。

### E. 资格与适配（"新生视角"的关键）
18. **13 科研助理**：**仅限大二及以上** → 大一（新生）看到应提示"你不符合年级要求"。
19. **08 校园软件项目组**：面向大一、大二，且"希望成员**了解 Git 基本操作**" → 资格 + 能力双重门槛。
20. **01 蓝桥杯训练营**："零基础可参加"、**11 科研入门**"面向全校学生" → 「零基础友好」是新生筛选的高价值标签。

> 另外注意材料里出现 **"计算机学院发布"（21）**、**"外国语学院发布"（26）**、**协会/校级**（多数）、**学生个人发布**（22–25）四类来源 —— 要求 2 的"合理呈现不同来源"就落在**来源标签分级**上。

## 四、产品方案：掌上猪科

**名字**：掌上猪科（"猪"取"珠"的谐音，校园口语化，降低距离感）
**一句话定位**：把校园里散落的活动与机会，变成"**今天/这周我能做什么、我够不够格、什么时候截止、这信息靠不靠谱**"。

### 目标用户
在校学生，**重点照顾新生**（信息渠道少、不熟悉校园通知体系、容易错过截止时间、容易踩到低质信息）。

### 核心功能（对应要求 3、4、5、6）

1. **活动发现 + 状态引擎**
   - 以"当前时间"实时计算状态：进行中 / 今日开始 / 即将截止（≤24h）/ 已截止可候补 / 已结束·回放待上线 / 长期有效 / 待定
   - 快捷筛选：今日、三天内、本周、即将截止、零基础友好、仅看我够格
   - 搜索 + 按来源（学院/协会/学生）与类型（比赛/招募/讲座/学习/志愿/文体）分类
2. **活动详情（结构化解读）**
   - 关键要素卡片：时间、地点、对象、报名方式、费用、截止时间（**缺失项显式标注"未提供/待确认"**）
   - **关联通知区**：合并 01+09、03+20，并用"变更点"高亮（时间 9/20→9/21、地点→实验楼 A402、开发名额已满）
   - 风险/提示区：24 加私人微信、25 疑似商家推广 → 风险标签与提醒
3. **收藏与报名（闭环 + 持久化）**
   - 收藏、报名/意向登记、候补意愿；刷新/重开后保留（localStorage）
   - "我的"页面：我的收藏、我报名的、倒计时提醒（今天/明天截止）、我的发布
4. **学生自主发布**
   - 表单填写后**直接进入列表**，标注"学生发布 · 未验证"，并自动做可疑词检测（加私人微信、日结、外链购买）
   - 自己发布的内容可编辑/删除，形成完整使用流程

### 创新功能（对应要求 7，三项中落地 2–3 项）

- **A. 信息可信度与完整度评分**：按"来源层级 + 必备字段完整度 + 可疑特征"给出评分与缺失项清单，让人**一眼看出信息能不能信**（直接对应 24/25 与 P033）。
- **B. 资格适配（"我能参加吗"）**：用户设置年级/基础/每周可投入时间 → 自动判定 "符合 / 不符合 / 待确认"，把 13（仅大二↑）、08（大一大二+Git）、14（限 40 人需审核）等门槛变成显式结论，**新生不用逐条读判断**。
- **C. 变更与冲突合并提示**：自动识别同一活动的多通知并显示"**已变更**"（01/09、03/20），避免看到失效时间。

### 技术方案（Pages 能直发的最稳路线）

```
/
├── index.html          # 单页应用入口
├── assets/css/app.css  # 设计系统（配色/间距/组件）
├── assets/js/
│   ├── data.js         # 26 条材料的结构化数据（来源/状态/缺失字段/关联关系）
│   ├── engine.js       # 状态引擎：时间判定、筛选、搜索、可信度评分
│   ├── store.js        # localStorage 持久化层
│   └── app.js          # 视图渲染与交互（列表/详情/我的/发布）
└── README.md
```
- **零构建、零依赖**：不用 Vue/Vite，避免 Pages 路径与构建配置翻车（提交说明 P016 也提示了框架需额外配置）
- 手机优先响应式（新生主要用手机看通知）
- 纯静态 → main 分支根目录直接开启 Pages
