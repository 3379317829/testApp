# 掌上猪科 · 产品方案

> 项目：珠海科技学院计算机协会软件部 2026 年秋季纳新第二轮考核
> 交付物：GitHub 仓库（源码 + 文档） + GitHub Pages 在线作品

---

## 一、交付要求

| 项 | 要求 |
|---|---|
| 提交物 | ① GitHub 仓库链接 ② GitHub Pages 在线作品链接（评委不下载、不安装，点开即可体验） |
| 仓库 | Public，含完整源码与 README，不少于 3 次有实际意义的提交，不建议仅在结束前一次性上传 |
| 技术形态 | Pages 只承载静态前端，**核心体验不依赖未提供的服务器或后端** |
| 禁止项 | 不提交账号密码、API Key、Token 等敏感信息 |
| README | 产品名称、解决的问题、主要功能、运行与使用说明、自主设计的实用或创新内容 |

据此确定技术路线：**纯静态前端 + localStorage 持久化**，不引入构建工具与后端依赖。

## 三、材料的呈现原则

26 条校园信息中，有多处需要按"对用户负责"的方式呈现。归纳为五类处理原则，是产品设计的主要依据。

### 3.1 同一活动的多条通知需要合并

| 材料 | 处理方式 |
|---|---|
| 01 与 09 | 09 为 01 的补充通知：首次训练由 9 月 20 日改为 **9 月 21 日 19:30**，地点改为 **实验楼 A402**。两条并列会让用户看到已被推翻的旧时间 → 合并展示，并标出变更项 |
| 03 与 20 | 20 为 03 的补充说明：**开发方向名额已满**，现主要补充设计与材料成员，已投递者无需重复提交 → 合并后呈现"开发已满，仅补设计与材料" |

### 3.2 状态不止"开始 / 结束"两档

以材料设定的时间背景（9 月 19 日）为基准：

- 10 号交流会 9/19 15:00—16:30 → 处于**正在进行**状态
- 02 号公开课 9/19 19:00、18 号小组交流 9/19 19:30 → **今天稍后开始**，应给出剩余时间提示
- 04 号分享会 9/18 已结束，但材料注明"预计 9 月 20 日上传回放" → 状态为**已结束 · 回放待上线**
- 19 号路演报名 9/18 22:00 已截止，但注明"现场仍有余位可候补入场" → 状态为**报名已截止 · 可现场候补**
- 05 号志愿服务：活动 9/27，报名 9/20 12:00 截止 → 未开始但报名窗口临近关闭
- 07 号挑战赛：9/21 18:00 校内意向登记、10/20 提交作品，且材料明确"意向登记不等同于最终作品提交" → 拆分为**两个性质不同的截止时间**
- 14 号工作坊：限 40 人，且"提交报名表不代表最终录取，以审核通知为准" → 报名后状态为**待审核**

因此状态引擎按当前时间实时计算，而非写死为"未开始 / 已结束"。

### 3.3 缺失与不确定字段必须显式标注，不做补全

| 材料 | 处理方式 |
|---|---|
| 12 号挑战赛 | 费用信息未提供 → 显示「无」，不写"免费" |
| 16 号志愿者招募 | 未注明报名截止时间 → 标为长期有效 |
| 06 号学习小组 | 未注明报名时间，满员即止 → 如实标注 |
| 22 号约球、23 号搭子招募 | 场地待确认、地点未确定、时间仅为"拟于 9 月 21 日晚" → 均按待定处理 |
| 25 号体验交流 | 活动时间、地点均未注明 → 如实标注 |

### 3.4 信息质量与使用秩序需要机制而非一刀切

- 24 号："零门槛、日结"，要求添加私人微信获取详情，未提供主办方、地点与完整内容 → 属低可信信息，应给出**风险提示**
- 25 号：标题为技术交流，正文为商家优惠与购买链接 → 标题与内容不符，应标注**疑似推广**
- 学生自主发布共 4 条（22—25），其中 2 条存在问题 → 需要"来源标签 + 可信度评分 + 风险提示"的组合机制，在保持开放发布的同时控制信息质量

### 3.5 资格门槛需要显式判断

- 13 号科研助理：**仅限大二及以上** → 低年级学生应看到"不符合年级要求"的明确结论
- 08 号项目组：面向大一、大二，且要求了解 Git 基本操作 → 年级与能力双重门槛
- 01 号训练营"零基础可参加"、11 号分享会"面向全校学生" → 「零基础友好」是新生筛选的高价值标签

### 3.6 来源分层

材料中出现四类来源：学院发布（21、26）、协会与校级（多数）、学生个人发布（22—25）。来源分级是需求 2「合理呈现不同来源」的落点。

## 四、产品设计

**名称**：掌上猪科（取"珠"的谐音，贴近校园语感）
**定位**：把校园里散落的活动与机会，整理成"今天能做什么、我够不够条件、什么时候截止、信息是否可靠"。

### 目标用户

在校学生，**重点覆盖新生**：信息渠道少、不熟悉校园通知体系、容易错过截止时间、容易接触低质信息。

### 核心功能

**1. 活动发现与状态引擎**

- 按当前时间实时计算状态：正在进行 / 今天开始 / 即将截止 / 报名中 / 报名已截止可候补 / 即将开始 / 长期有效 / 已结束待回放 / 时间未提供
- 快捷筛选与多维度筛选：分类、来源、关键词搜索、只看符合条件的信息
- 列表分页浏览，每页固定条数

**2. 活动详情结构化解读**

- 时间、地点、面向对象、参加要求、报名方式、预估费用、招募人数、发布方逐项列出
- 材料未提供的字段统一显示「无」，并单独列出未提供项，不做推断
- 关联通知合并：同一活动的多条通知合并展示并标出变更点
- 保留材料原文，信息可追溯

**3. 收藏与报名闭环**

- 收藏、报名登记、候补意愿；操作结果本地持久化
- 「我的」页面提供收藏、已报名、我发布的三个视图与临近截止提醒

**4. 学生自主发布**

- 发布内容经实名账号提交后进入发现页列表，标注来源与发布者实名信息
- 自动检测可疑内容（日结兼职、加私人微信、商家链接等）并附加风险提示
- 发布需勾选实名发布承诺，违规内容由后台核查处理

**5. 账号与实名认证**

- 使用学号与「我的珠科」APP 密码登录，由学校统一身份认证服务核验身份
- 账号绑定学号并采用实名制，同一学号仅可绑定一个账号
- 实名认证后自动绑定姓名与学号；未实名账号不能发布、报名或登记参加活动
- 尚未开通账号的学号可通过身份核验直接开通并登录

**6. 后台管理**

- 账号总览统计、新增账号、封禁与解封、删除账号（同时移除其发布内容）
- 查看账号发布内容并下架违规内容；风险内容提供快捷核查入口

### 自主设计的功能

- **信息可信度与完整度评分**：综合来源层级、必备字段完整度与可疑特征给出评分与缺失项清单，让信息质量可量化
- **资格适配**：用户设置年级、基础水平与每周可投入时间后，自动判定「符合 / 不符合 / 待确认」，把隐含门槛转为显式结论
- **关联通知与变更合并**：自动识别同一活动的多份通知，标出已变更的时间与地点，避免用户看到失效信息

### 技术方案

```
/
├── index.html              # 单页应用入口
├── assets/
│   ├── css/app.css         # 设计系统与组件样式
│   └── js/
│       ├── data.js         # 26 条材料的结构化数据（来源、时间、缺失字段、关联关系）
│       ├── engine.js       # 状态引擎：时间判定、筛选、搜索、可信度评分、资格适配
│       ├── store.js        # localStorage 持久化层
│       ├── account.js      # 账号体系与统一身份认证接口
│       ├── app.js          # 视图渲染与交互
│       ├── detail.js       # 活动详情与关联合并
│       ├── mine.js         # 收藏、报名、我的发布
│       ├── publish.js      # 学生自主发布
│       └── admin.js        # 后台管理
├── docs/                   # 方案与设计文档
├── screenshots/            # 界面截图
└── README.md
```

- 零构建、零依赖：不引入前端框架，避免部署路径与构建配置带来的额外风险
- 移动端优先的响应式设计
- 纯静态站点，main 分支根目录直接开启 GitHub Pages

### 提交规划

按功能分阶段提交，覆盖：项目结构与文档 → 材料数据录入 → 状态引擎与列表 → 详情与关联合并 → 收藏与报名持久化 → 学生自主发布 → 账号登录与实名认证 → 后台管理 → 文案与交互打磨 → 文档完善。完整提交历史见仓库记录。

## 五、风险控制

| 风险 | 应对 |
|---|---|
| Pages 部署存在延迟 | 尽早开启 Pages 并预留检查时间，每次推送后复核线上文件 |
| 赶进度容易遗漏信息呈现的细节 | 数据层先标记缺失、待定与关联关系，界面只负责渲染 |
| 敏感信息误入仓库 | 不提交账号密码、API Key、Token；提交前检查暂存区 |
| 演示环境缺少后端 | 涉及服务端能力的功能保留接口形态并注明当前实现方式，页面上如实说明 |
